# 企业级项目完善优化方案

## Context

本项目作为全栈学习项目，技术栈选型现代（FastAPI + Vue3 + Celery + PostgreSQL），基础架构合理（四段式 AI 服务设计、分层清晰、Docker 编排完善）。但从企业级标准来看，在自动化流程、质量保障、可观测性、安全加固等维度存在明显缺口。当前综合成熟度约 7/10，需要补齐以下关键技术能力。

---

## 当前项目优势（已做好的部分）

- 结构化 JSON 日志 + request_id 全链路追踪
- JWT 认证 + Token 刷新机制完整
- Alembic 数据库迁移体系
- Pydantic Settings 多环境配置
- Docker + Compose 开发/生产双环境
- API 契约管理（packages/contracts/）
- 前端 axios 拦截器、路由守卫
- 严格 TypeScript 配置

## Task 1：全局错误处理与标准化响应（后端核心）

**目标**：统一 API 错误响应格式，实现全局异常处理

**具体工作**：
- 创建 `app/core/exceptions.py`：自定义业务异常基类（`AppException`、`NotFoundError`、`ValidationError`、`AuthenticationError` 等）
- 在 `main.py` 注册全局异常处理器（`@app.exception_handler`）
- 统一错误响应格式：`{ "error": { "code": "RESOURCE_NOT_FOUND", "message": "...", "details": [...] } }`
- 替换所有裸 `HTTPException` 为自定义异常

**关键文件**：
- `apps/api/app/core/exceptions.py`（新建）
- `apps/api/app/main.py`
- `apps/api/app/modules/*/router.py`

---

## Task 2：速率限制与安全加固

**目标**：防止 API 滥用，增强生产安全性

**具体工作**：
- 集成 SlowAPI 实现速率限制（登录 5次/分钟，上传 10次/分钟，通用 60次/分钟）
- Nginx 添加安全头：`X-Frame-Options`、`X-Content-Type-Options`、`Strict-Transport-Security`、`Content-Security-Policy`
- 添加请求体大小限制中间件
- 添加请求超时中间件
- 验证生产环境 JWT_SECRET_KEY 强度

**关键文件**：
- `apps/api/app/main.py`
- `apps/api/requirements.txt`
- `infra/nginx/default.conf`

---

## Task 3：Celery 任务健壮性

**目标**：生产级异步任务处理

**具体工作**：
- 配置 `task_acks_late`、`task_time_limit`（3600s）、`task_soft_time_limit`（3300s）
- 实现指数退避重试策略（max_retries=3）
- 添加任务失败回调（`on_failure`）记录到数据库
- 配置死信队列（DLQ）处理多次失败的任务
- 添加 Flower 监控（docker-compose 中加入 flower 服务）

**关键文件**：
- `apps/api/app/core/celery_app.py`
- `apps/api/app/tasks/analyze_photo.py`
- `infra/docker-compose.yml`

## Task 4：数据库连接池与查询优化

**目标**：生产级数据库配置

- 添加数据库备份脚本（pg_dump 定时任务）

**关键文件**：
- `apps/api/app/core/database.py`
- `apps/api/app/models/*.py`
- `apps/api/app/modules/analysis/router.py`

## 验证方式

每个 Task 完成后的验证标准：
1. **Task 1**：故意触发不同错误，验证响应格式统一
2. **Task 2**：使用 ab/wrk 压测验证限流生效
3. **Task 3**：手动制造任务失败，验证重试和 DLQ
4. **Task 4**：使用 `EXPLAIN ANALYZE` 验证查询优化
5. **Task 5**：`docker compose up` 后 `curl /health` 返回各依赖状态
6. **Task 6**：`npm run lint` 和 `npm run test` 通过
7. **Task 7**：Push 代码触发 CI，PR 显示检查状态
8. **Task 8**：Grafana Dashboard 显示实时请求指标
9. **Task 9**：路由文件行数减少 50%+，测试仍通过
10. **Task 10**：`pytest --cov` 报告覆盖率 > 60%
11. **Task 11**：`pip-audit` 无高危漏洞
12. **Task 12**：Swagger UI 显示完整示例和描述
